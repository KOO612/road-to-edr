## 1. 핵심 개념

### `main` 함수 = 진입점(entry point)
- Node는 파일 맨 위부터 실행되지만, C++은 OS가 `main`을 찾아 호출하면서 시작한다.
- `return 0;`은 정상 종료, 0이 아닌 값은 오류 종료를 뜻하는 **종료 코드(exit code)**다.
- 반환값을 바꿔도 프로그램 동작은 같다. 이 값을 보고 판단하는 건 실행시킨 쪽(스크립트, CI, PowerShell의 `$LASTEXITCODE`)이다.
- 🔐 EDR 같은 보안 SW도 진입점(`main`/`ServiceMain`/`WinMain`)에서 시작한다. 악성코드 분석도 진입점을 찾는 데서 출발한다.

### `#include`와 전처리기
- 헤더 내용을 **컴파일하기 전에 그 자리에 텍스트째 복붙**한다. (`require`는 실행 중에 모듈을 불러온다는 점이 다르다.)
- `< >`는 표준/시스템 헤더, `" "`는 내가 만든 헤더에 쓴다.
- 쓰는 기능의 헤더는 직접 include한다. (`std::string`을 쓰면 `<string>`)

### `std::` 네임스페이스
- 표준 라이브러리 이름에 붙이는 "소속 이름표"다. 이름 충돌을 막아 준다.
- `using namespace std;`는 쓰지 않고 `std::`를 붙이는 습관을 들인다.

### 입출력
| 도구 | 용도 | 비고 |
|---|---|---|
| `std::cout <<` | 일반 출력 | `console.log` |
| `std::cerr <<` | 에러 출력 | `console.error` |
| `std::cin >>` | 토큰 단위 입력 | **공백/엔터에서 멈춘다** |
| `std::getline(std::cin, s)` | 한 줄 전체 입력 | **`\n`까지 읽는다** |

- `std::endl`은 줄바꿈과 flush를 함께 한다. 단순 줄바꿈은 `"\n"`으로 충분하다.
- `cin`은 입력을 읽기 전에 `cout`을 자동으로 flush한다. 그래서 줄바꿈 없는 프롬프트도 잘 보인다.

### 빌드 3단계
```
.cpp ──①전처리──▶ 확장된 .cpp ──②컴파일──▶ .obj ──③링크──▶ .exe
```
- ① 전처리: `#` 지시문을 처리한다(include 붙여넣기 등).
- ② 컴파일: 문법을 검사하고 기계어로 번역한다. **`.cpp` 하나당 `.obj` 하나**가 나온다. 에러 코드는 **`C`**로 시작한다(예: 오타 `std::cuot`).
- ③ 링크: 여러 `.obj`와 라이브러리를 묶어 `.exe` **하나**를 만든다. 선언은 있는데 구현을 못 찾으면 에러가 나고, 에러 코드는 **`LNK`**로 시작한다(예: `LNK2019`).
- 🔐 링커가 만드는 `.exe`가 **PE 파일**이다. 임포트 테이블도 링크 단계에서 만들어진다(나중에 PE 파서로 연결된다).

### 입력 버퍼
- `cin >>`가 가져가지 않은 입력은 **버퍼에 그대로 남고**, 다음 입력 함수가 기다리지 않고 가져간다.
  - `"Kim Minsu"`를 `cin >> a; cin >> b;`로 읽으면 a=`Kim`, b=`Minsu`가 된다.
  - `cin >> age;` 다음에 `getline`을 쓰면 남은 `\n` 때문에 **빈 문자열로 바로 끝난다**. 해결: `std::cin >> std::ws;` 또는 `cin.ignore(...)`

### 입력 실패(fail state)
- `int`에 `abc`를 넣으면 읽기에 실패하고, 변수에 **0**이 들어가며(C++11부터) cin에 실패 깃발이 선다.
- 깃발이 선 다음부터는 **이후의 `cin >>`이 전부 기다리지 않고 즉시 실패한다**. 이때 읽기를 시도조차 안 한 변수는 값이 바뀌지 않는다.
- 제대로 처리하는 방법(`if (!std::cin)`)은 Day 18에서 배운다.

### 연산자 주의점
- `=`는 대입, `==`는 비교다(JS와 같다).
- `int / int`는 결과도 `int`이고 소수점은 **버린다**(`10 / 3 = 3`).
- `%`는 **정수 전용**이다. 변수를 `double`로 바꾸면 `%`가 컴파일 에러가 난다.
- 정수를 0으로 나누면 JS처럼 `Infinity`가 나오지 않고 오류(크래시)가 난다. 반드시 미리 검사한다.

## 3. 막혔던 부분과 해결

1. **`if (num1 = 0 || num2 = 0)` 컴파일 에러(C2106)**
   - 원인 ①: 비교(`==`) 대신 대입(`=`)을 썼다.
   - 원인 ②: `||`가 `=`보다 우선순위가 높아서 `num1 = ((0 || num2) = 0)`으로 해석됐다. 임시 값(l-value가 아닌 값)에 대입하려 해서 에러가 났다.
   - ⚠️ `if (num2 = 0)`처럼 쓰면 에러 없이 컴파일되고 검사가 **조용히 무력화**된다. (2003년 리눅스 커널 `uid = 0` 백도어 시도 사례) MSVC `/W4`를 켜면 경고 C4706이 뜬다.
   - 해결: `if (num2 == 0)`
2. **"cin >> 뒤에 남은 입력은 어디로?"**: 처음엔 "버퍼가 비워진다"고 답했다. 실제로는 버퍼에 남아 다음 입력이 가져간다. 체크 질문에서는 `\n` 잔류로 정확히 설명했다.
